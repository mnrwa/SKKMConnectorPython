# SKKM Connector Python

Библиотека `rbsoftskkm` — программная обёртка над REST API **Сервера ККМ** для приложений на Python.

Позволяет добавить печать чеков и управление ККТ в любое Python-приложение без ручной сборки HTTP-запросов и JSON. Работа строится вокруг одного класса `SkkmConnector`: заполняете свойства, вызываете метод, читаете результат из свойств.

# 1. Возможности

- **Полное покрытие REST API Сервера ККМ 4.0** — печать чеков, возвраты и коррекции, открытие и закрытие смены, X/Z-отчёты и отчёт о расчётах, внесение и выемка наличных, слипы, картинки, маркировка, фискализация, очередь печати, шаблоны, операции, а также администрирование (пользователи, настройки службы, пулы, добавление и изменение ККТ).
- **Простой доступ** — один объект `SkkmConnector`: заполняете свойства, вызываете метод, читаете результат из свойств — без ручной сборки HTTP-запросов.
- **Синхронный и асинхронный режим** — ждать ответ на кассе или поставить задание в очередь и опросить статус позже.
- **Состояние касс** — список устройств с сервера, сведения о ККТ, статус смены, счётчики, остаток наличных.

# 2. Требования

- **Платформа:** Python 3.10 и новее; единственная зависимость — `httpx`;
- **Доступный Сервер ККМ 4.0 -** доступная служба печати (по умолчанию TCP-порт `4398`); если на сервере выключен анонимный доступ - токен авторизации пользователя.

Системный прокси используется с учётом его списка исключений; `localhost` и `127.0.0.1`
всегда подключаются напрямую.

# 3. Структура библиотеки

```
src/rbsoftskkm/
├── core/   — класс SkkmConnector: подключение, методы API, состояние, разбор ответов
├── dto/    — публичные типы: позиции чека, оплаты, покупатель, перечисления, результаты
└── data/   — внутренний HTTP-транспорт и контракты обмена с сервером
```

Класс `SkkmConnector` собран из цепочки модулей `core/`: состояние, подключение,
входные свойства, внутренние помощники, сборка тел запросов и методы API. Для
приложения это один класс — импортируется из корня пакета:

```python
from rbsoftskkm import SkkmConnector
```

Ограничения:

- объект не потокобезопасен - на параллельную работу создавайте отдельные экземпляры;
- коннектор не валидирует состав чека - неверные данные отвергнет сервер;
- после `Dispose()` экземпляр использовать нельзя. Коннектор поддерживает `with`:
  `with SkkmConnector() as kkm: ...` вызовет `Dispose()` на выходе из блока.

## 3.3 Соглашения об именах и режим работы

Три решения, принятых один раз для всей библиотеки.

**Имена классов, полей и методов — как в эталонной реализации: `PrintCheck`,
`FiscalLine.Quantity`, `TaxSystem.ОСН`.** Это расходится с PEP 8, где поля и методы
пишутся в snake_case. Размен осознанный: коннектор существует на нескольких языках,
и один и тот же чек должен собираться одинаково во всех — тогда документация, примеры
и код клиента переносятся между реализациями без правок. Имена файлов и модулей
остаются snake_case, как требует система импортов Python. Внутренние помощники
(`_get`, `_post`, `_read_result`) тоже snake_case: они не часть публичного API.

Единственное исключение — `BarcodePrintText.None`: в Python `None` — ключевое слово,
поэтому элемент называется `None_`. Значение (`0`) и место в перечислении не изменились.

**Методы синхронные.** Вызов `kkm.PrintCheck()` возвращает управление, когда ответ
разобран; результат читается из свойств. Прикладной код обычно синхронный, а
интерфейсным приложениям всё равно нужен рабочий поток: демо на PySide6 запускает
пример в `QThreadPool`. Отмена работает из другого потока: `kkm.Cancel()` прерывает
ожидание, вызов завершается с `ErrorCode = -3`.

**Модели — датаклассы стандартной библиотеки.** Сериализация своя (`data/json_codec.py`):
чтение ответов нечувствительно к регистру имён (сервер отдаёт часть полей в camelCase),
при записи тела запроса поля со значением `None` не сериализуются, `Decimal` пишется
числом без потери точности. Внешних зависимостей, кроме `httpx`, нет.

Денежные суммы — всегда `decimal.Decimal`, не `float`: округление float даёт суммы,
которые сервер отвергает.

# 5. Пример работы с ККТ

```python
from rbsoftskkm import Cashier, SkkmConnector

# 1. Создаём объект коннектора
with SkkmConnector() as kkm:
    # 2. Настраиваем параметры подключения
    # 2.1. Хост и порт (порт по умолчанию — 4398)
    kkm.Host = "127.0.0.1"
    kkm.Port = 4398

    # 2.2. Имя ККМ, заданное на стороне сервера ККМ
    kkm.DeviceName = "Atol"

    # 2.3. Токен авторизации из профиля пользователя сервера ККМ
    kkm.Token = "a6261fa7-6675-41c6-a9f5-cee920e1d71c"

    kkm.Cashier = Cashier(Name="Иванов А.И.")

    # 3. Подключение: при успехе параметры ККМ уже в свойствах
    kkm.Connect()

    # 4. Анализируем ответ — обработчик уже разложил Success/Code/Description и Result
    if kkm.Ok:
        ffd = kkm.Kkt.Device.FfdVersion if kkm.Kkt and kkm.Kkt.Device else ""
        print(f"Длина строки: {kkm.LineLength}, место: {kkm.SaleLocation}, ФФД: {ffd}")
    else:
        print(f"{kkm.ErrorCode}: {kkm.ErrorDescription}")
```

Если подключение прошло успешно — можно вызывать методы работы с ККТ:

# 5. Открываем кассовую смену
kkm.OpenShift()
